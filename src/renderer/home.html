Navigation

              
.Yo is a multi-panel workspace. You can view one app at a time, or split the screen into a grid of panels. Every panel is a live web app running inside .Yo.


              
Switching panels

              
Use the .dip command to switch between panels. Type it in the command bar (Cmd+>) or the agent panel.

              
.dip claudeSwitch to Claude

              
.dip gmailSwitch to Gmail

              
.dip backGo to the previous panel

              
You can also click on tabs in the tab bar to switch panels.


              
Split view

              
Put multiple panels side by side with .dip split.

              
.dip split claude gptTwo panels side by side

              
.dip split claude gpt / gemini code2×2 grid — / separates rows


              
URL bar

              
The URL bar at the top shows the current panel's address. You can type any URL to navigate, or use it as a search bar (searches Google by default). Use Cmd+L to focus it.


              
Keyboard shortcuts

              
⌘.Toggle the .Yo agent panel

              
⌘>Open the command bar

              
⌘LFocus the URL bar

              
⌘RRefresh the active panel

              
⌘+Zoom in

              
⌘-Zoom out

              
EscClose current overlay

            


            

              
Commands

              
Commands are the core of .Yo. Type them in the command bar (Cmd+>), inside any panel, or chain them together. Every command starts with a dot.


              
.yo — Agent

              
Opens the AI agent panel. The agent can search your captures, run shell commands, navigate panels, and more. Works from any panel.

              
.yoOpen the agent panel

              
.yo find my notes about pricingAgent searches your captures

              
.yo what was my last git commitAgent runs read-only shell commands


              
.yo . — Inline process

              
Processes the last .sup capture with a prompt and injects the result directly into the active text field. No agent panel — just capture, switch, and process.

              
.yo . summarize thisSummarize and inject into text field

              
.yo . rewrite as bullet pointsTransform captured content inline


              
.sup — Capture

              
Manually captures the active panel into memory and your clipboard. Panels also auto-capture on blur and navigation — this is for explicit capture or processing.

              
.supCapture to memory + clipboard

              
.sup . formalizeCapture + run the "formalize" skill

              
.sup . translate to spanishCapture + run a freeform prompt

              
.sup ..Capture last agent result into the text field


              
.dip — Navigate

              
Switches panels, creates split views, restores layouts, and chains app commands.

              
.dip claudeSwitch to a panel

              
.dip split claude gptSide by side

              
.dip layout workspaceRestore a saved layout

              
.dip claude newSwitch + run app commands

              
.dip gmail composeSwitch to Gmail + open compose


              
.drip — Effects

              
Visual celebration effects. Reward yourself.

              
.dripDefault fireworks effect

              
.drip 3 fireworks, heartsStacked count + mixed effects


              
.council — Multi-model debate

              
Convene a council of LLMs to debate a topic. Name the models you want, then state the prompt. The .yo agent moderates rounds, and you get diverse perspectives from different providers.

              
.council grok claude gemini what came first the chicken or eggThree models debate a question

              
.council claude gemini should we use Postgres or MongoTwo models, architecture decision


              
Chaining

              
Commands can be chained together. Each command runs in sequence.

              
.dip claude newSwitch to Claude, then start new chat

              
.sup .dip gpt .yo . explain thisCapture, switch to GPT, process inline

            


            

              
Apps

              
Apps are web applications that run inside .Yo panels. Each app has an ID, a URL, and a set of mapped commands that the agent can execute.


              
Pre-configured apps

              
.Yo ships with pre-configured apps including ChatGPT, Claude, Gemini, Gmail, Slack, GitHub, Linear, Notion, Grok, Perplexity, YouTube, Reddit, Google Docs, and X. Each has commands mapped to their specific UI elements.


              
Adding apps

              
Open the Apps page in this help panel and click + New. Give it an ID (used in commands like .dip myapp), a name, and a URL. You can optionally map commands.


              
App commands

              
Commands are actions mapped to specific selectors in the app's DOM. Common commands:

              
grabExtract the main content as text

              
inputFocus the text input field

              
submitClick the send/submit button

              
newStart a new conversation/document

              
searchFocus the search bar

              
composeOpen compose window (email)

              
The .yo agent uses these commands when navigating for you. You can also run app commands via .dip claude new (switch + execute).


              
Force web mode

              
Some apps (like ChatGPT, Claude, Gmail) need to run in a web view instead of Electron's BrowserView. This is the "Force Web" toggle — enable it if the app doesn't render correctly.


              
Do Not Record

              
Prevents ambient capture of sensitive apps. When enabled, the app's content is never captured on blur or navigation. Banking, health, password manager, and tax/gov domains are blocked by default. Toggle per-app in the app detail view.

            


            

              
Skills

              
Skills are reusable prompt templates that process captured content. Think of them as saved instructions — capture something with .sup, then apply a skill to transform it.


              
Using skills

              
.sup . summarizeCapture + run the "summarize" skill

              
.sup . formalizeCapture + formalize the text

              
.yo . summarizeProcess last capture with a skill

              
When you use .sup . skillname, the content is captured and then processed through the skill's prompt template. The result replaces your clipboard content.

              
When you use .yo . skillname, the result is injected directly into the active text field.


              
Creating skills

              
Go to the Skills page in this panel and click + New. Each skill has:

              
    
                
  • Name — the keyword you use to invoke it (e.g., "summarize")
    • 
                
  • Prompt — the instruction template. Use {{input}} as a placeholder for the captured content.
    • 
              

              
Example prompt: Summarize the following in 3 bullet points:\n\n{{input}}

              
The .yo agent can also create skills for you — just ask: .yo create a skill called translate that converts text to Spanish

            


            

              
Layouts

              
Layouts save your panel arrangement so you can restore it later with one command. Save a 3-panel workspace, switch away, and come back to it instantly.


              
Saving layouts

              
Arrange your panels the way you want (using .dip split or .dip grid), then save:

              
Save layouts from the Layouts page in this panel, or ask the .yo agent to save one for you.


              
Restoring layouts

              
.dip layout workspaceRestore the "workspace" layout

              
This restores the exact panel arrangement, sizes, and apps that were active when you saved.


              
Grid layouts

              
For advanced arrangements, use .dip grid with column/row spans and custom sizing:

              
.dip grid claude,gpt / gemini,code2×2 grid

              
.dip grid claude:2,gpt / gemini,codeClaude spans 2 columns

              
.dip grid [70,30] claude,gpt70/30 split

              
Drag the grid handles between panels to resize them live.

            



            

              
Dev Spaces

              
A dev space is a workspace bound to a project directory plus a team of named code-terminal agents that coordinate through a shared event log. Each agent runs its own Claude Code session with a role, an inbox, and a shared MCP toolkit for talking to the team.


              
Workspaces

              
A workspace binds a yo session to a project directory. Captures, agents, and layouts are scoped to it. The active workspace persists across app restarts. Manage workspaces from the Workspaces page in this help panel.

              
Storage: ~/yo/workspaces.json (index) + ~/yo/workspaces/<slug>/ (per-workspace event log, agent metadata, inbox state).


              
Scaffolding agents

              
A code-terminal is a named pty panel running an LLM CLI (default claude) in the workspace's rootDir. Each agent has a name and a role. Configure agents from the Agents page in this help panel.


              
How agents coordinate

              
Each code-terminal boots with YO_AGENT_NAME and YO_WORKSPACE in its env, plus a project-local CLAUDE.md dispatcher and a .mcp.json pointing at the MCP server. Agents see a personalized briefing at ${rootDir}/.yo/agents/<name>.md.

              
The MCP server (loopback HTTP, bearer token auth) exposes:

              
    
                
  • team_status() — list agents, roles, last-post timestamps
    • 
                
  • read_log(filter?) — read the event log; filter by tag/from/to/kind/time
    • 
                
  • read_agent(name, kind?) — read another agent's scratchpad or post history
    • 
                
  • post(body, tags?, kind?, refs?) — append to the team event log
    • 
                
  • post_to(agent, body, tags?) — direct message, fast-path delivery
    • 
                
  • subscribe(filter) / unsubscribe(id) — manage tag-filter subscriptions
    • 
              


              
Default subscriptions

              
Auto-added on agent creation: mentions_me, role:<my-role>, broadcast.


              
Sender conventions

              
    
                
  • Status updates → post(body, tags: ["broadcast"])
    • 
                
  • Cross-role asks → post_to("server", body) or post(body, tags: ["role:server"])
    • 
                
  • Internal scratch → post(body) with no tags (logged but not delivered)
    • 
                
  • Use tag blocking for anything that needs a teammate response
    • 
              


              
Inbox delivery

              
When an event lands and an agent has a matching subscription, the orchestrator appends it to ${rootDir}/.yo/inbox/<agent>.md (rolling tail of the last 50 events). Each agent's CLAUDE.md instructs it to read this file at the start of every turn — events newer than its last activity are new.


              
Storage layout

              
~/yo/workspaces.json                           # workspace index
~/yo/workspaces/<slug>/agents.json             # roster + subscriptions
~/yo/workspaces/<slug>/events.jsonl            # append-only event log
~/yo/workspaces/<slug>/inbox-state.json        # per-agent lastDeliveredTs
${rootDir}/.mcp.json                           # MCP config (managed)
${rootDir}/CLAUDE.md                           # dispatcher section (managed)
${rootDir}/.yo/agents/<name>.md                # per-agent role briefing
${rootDir}/.yo/inbox/<name>.md                 # per-agent inbox


              
Embedded VS Code

              
The built-in vscode panel is a code serve-web instance that runs your locally installed VS Code. On first launch, your Desktop VS Code settings.json and keybindings.json are copied into the embedded data dir so the editor inherits your preferences. Agents and the editor share rootDir, so file changes from agents appear live in the editor.

            


            

              
The .Yo Agent

              
The agent is your AI assistant that lives in the side panel. It searches your captures, runs shell commands, and executes workspace operations — all through natural language.


              
What it can do

              
    
                
  • Search captures — vector search across all ambient and manual captures
    • 
                
  • Run commands — read-only shell commands (git log, ls, cat, etc.)
    • 
                
  • Read files — read any file under your home directory
    • 
                
  • Search notes — keyword search across saved notes in ~/yo/notes/
    • 
                
  • Format — apply skills to transform content
    • 
                
  • Save memory — remember preferences and patterns for future conversations
    • 
              


              
Agent modes

              
The mode selector at the bottom of the agent panel controls how the agent uses its tools. Every tool is classified as either observe (read-only, safe) or mutate (has side effects). The mode determines what happens when the agent wants to use a tool.


              
askEvery tool requires your approval before running (default)

              
The safest mode. The agent will describe what it wants to do and wait for you to approve or deny each action. Good for learning what the agent can do.


              
planNo tools run — agent only outlines its plan

              
The agent thinks through what it would do and shows you a numbered plan, but never executes anything. Use this to preview the agent's approach before switching to ask or auto.


              
autoObserve tools run immediately, mutate tools still ask

              
Read-only tools (search captures, get context, read files, run commands, list files, search notes) execute without confirmation. Tools that change state (save memory, etc.) still require your approval. The balance between speed and safety.


              
Tool permissions

              
You can override the mode for individual tools in Settings > Agent > Tool Permissions. Each tool can be set to:

              
    
                
  • Default — follows the global mode above
    • 
                
  • Auto — always runs without asking, regardless of mode
    • 
                
  • Ask — always asks for approval, even in auto mode
    • 
              

              
For example, you might set search_captures to "auto" so the agent can always search freely, while keeping save_memory on "ask" so it always confirms before persisting state.


              
Ambient capture

              
Content is automatically captured when you switch away from a panel (blur) or navigate to a new page. SmartGrab extracts the meaningful content and indexes it for vector search. Apps marked "Do Not Record" are excluded. This means the agent can search everything you've looked at without you ever typing .sup.


              
Model selection

              
The model selector lets you choose which LLM powers the agent. Configure your API key and preferred provider in Settings > Model Configuration. Supports Anthropic, OpenAI, Google, xAI, and DeepSeek.


              
Chat history

              
Click the hamburger menu (☰) in the agent panel header to see your conversation history. Each conversation is saved automatically. Click + to start a new chat.

            


            

              
MCP (Model Context Protocol)

              
.Yo supports MCP in two ways: as a server that exposes your captures to external tools, and as a way to configure local MCP servers for the agent to use.


              
Yo MCP Server (expose captures)

              
Enable in Settings > General > MCP Server. This runs a local MCP server that lets external AI tools search your capture store — your ambient captures, .sup snapshots, and notes.

              
Use this when you want Claude Desktop, Cursor, Windsurf, or other MCP-compatible tools to access everything you've captured in .Yo. The server runs on your machine and uses bearer tokens for auth.


              
Connecting from Claude Desktop

              
Edit ~/Library/Application Support/Claude/claude_desktop_config.json:

              
{
  "mcpServers": {
    "yo": {
      "command": "curl",
      "args": ["-N", "-H", "Authorization: Bearer YOUR_TOKEN",
               "http://localhost:7860/sse"]
    }
  }
}

              
Replace YOUR_TOKEN with a token generated in Settings. The port defaults to 7860 but can be changed.


              
Connecting from Cursor / Windsurf

              
In your project's .cursor/mcp.json or MCP settings:

              
{
  "mcpServers": {
    "yo": {
      "url": "http://localhost:7860/sse",
      "headers": {
        "Authorization": "Bearer YOUR_TOKEN"
      }
    }
  }
}


              
Cloud vs Local tokens

              
The Yo MCP Server runs locally on your machine. External tools connect to it over localhost. No data leaves your computer — the MCP server just gives other tools a way to search your captures using the same vector index the .yo agent uses.

              
The tokens generated in Settings are local access tokens — they authenticate MCP clients connecting to your local server. These are separate from your LLM API keys (Anthropic, OpenAI, etc.) which are used by the .yo agent to generate responses.

              
    
                
  • MCP tokens — authenticate external tools connecting to your local Yo server. Free, no API costs.
    • 
                
  • LLM API keys — power the .yo agent's responses. Costs depend on your provider.
    • 
              

              
When Claude Desktop or Cursor calls your Yo MCP server, the search is local (no LLM tokens spent). But if those tools then use the search results in a prompt, that prompt uses their configured LLM — and those tokens come from your API key in that tool.


              
Available MCP tools

              
When connected, external tools can use:

              
    
                
  • search_captures — vector search across all your captured content
    • 
                
  • search_notes — keyword search across saved notes
    • 
                
  • read_note — read a specific note file
    • 
                
  • get_session — get the current session context
    •
